# 测试编写指导书：给能力有限的执行 Agent

状态：`DRAFT v1.0`。适配依据是用户报告的 MiniMax 本地执行问题，不是模型能力排行榜。模型、版本和额度由外部选定；下面任务卡不自行切换模型。

## 1. 不再给“把覆盖率做到90%”这种实施任务

分析者收到一个具体候选，实施者收到一个已经审查的测试配方。程序负责 Coverage 数字、工具命令、身份和落盘；Agent 负责理解行为、构造输入、说明预期。

一个工作包回答四个问题：**测谁、怎么进入、正确结果是什么、怎样证明测的就是它。** 缺任一关键答案，不开始盲写测试。

文件名含 ComprehensiveTest 不代表目标实现已被验证；mockStatic 也不是全局反模式。判断标准是当前明确要覆盖的方法是否真实执行，以及 Mock 是否绕过了决定进入该方法的条件。

## 2. Context Pack：给出材料，不让模型猜

由程序从已锁定工作区组装并记录内容哈希，默认包含：

1. Target：module、binary class、method、JVM descriptor、method counters；行号提示及可信级别。
2. 生产方法、关键调用入口/分派条件；必要 DTO/构造器/依赖方法签名。继承场景必须包含实际实例类型和 dispatch 位置。
3. 当前最相关的测试及 fixture；现有哪些地方 Mock 了目标、哪些确实调用真实实现。
4. 一个同测试模式、已通过真实执行与断言审查的本地样板；没有样板时明确标注，不假装存在。
5. 项目业务契约/批准样例/明确预期及其文件定位；没有足够依据时标 UNKNOWN。
6. 允许修改的测试文件、不可修改项、当前错误反馈、现有局部执行入口。

默认只给一个方法及其必要上下文，不灌整个包或几十份 Markdown。长方法允许按关键入口和目标分支切片，但不能剪掉控制条件。缺材料通过 `REQUEST_CONTEXT: 路径/符号 + 需要解决的问题` 向程序追加，不让实施者自己遍历整个私有仓库。

## 3. Analysis 配方

必须使用现有 GapAnalysisRecord；字段可适配已有 schema，不另建竞争状态源。最低内容如下。

| 项目 | 必须回答 | 错误示范 |
| --- | --- | --- |
| Target | 精确到 module/class/method/descriptor | Foo#convert，不知道重载 |
| Entry | 真实可调用入口及调用边，附源码定位 | 父类有 process，所以一定到子类loop2 |
| Conditions | 到目标分支前每个关键条件、数据和状态如何满足 | 多造几个对象试试 |
| Control | 输入、协作者或运行条件分别怎样控制，Mock影响什么 | Mock掉目标或关键 dispatch |
| Oracle | 预期输出/状态/错误及其依据 | 当前实现返回什么就断言什么 |
| Recipe | 精确 fixture、调用、断言清单、测试层级、保护的非目标行为 | “补正常异常边界” |
| Decision | PROCEED / ESCALATE / DEFER，附事实理由 | private即LOW，或者missed多即HIGH |

不要求完整符号执行。只把真正决定目标能否到达的条件列清。文件系统可用临时文件不自动等于集成测试；静态方法也不自动等于不可单测。用能可靠验证行为的最低成本层级。

预期依据优先是已确认契约、可独立核对的样例和有效已有测试。代码可以解释触发条件；仅从代码观察出的返回值只能作为 characterization hypothesis，不能覆盖或推翻已有业务契约。没有可信 oracle，提出需要的事实并延期，不把疑似 bug 固化成正确行为。

## 4. private/继承/运行时分派专用检查

以之前 private loop2 失败模式为警示，而非规定 loop2 必须集成测试：

- 写出实际 public/package 可测试入口与接收者具体类型。
- 找到进入目标方法的每一处调用和 guard；确认继承分派是否进入父实现、是否短路。
- 非空集合、业务 mode、查找结果、初始化状态、执行线程等逐项映射到 fixture。
- 检查 Mock/spy stub 有没有替换目标、关键中间层或上下文构建。
- 通过入口间接覆盖 private；不新增 public 测试门、不改变生产可见性、不默认用反射直调。
- 普通单测不能重现时，使用现有模块/组件测试能力；没有所需环境时延期并给具体缺失项。

分析者不能凭“同Class涨了+1”宣称可达。最终程序比较同一 descriptor 方法的真实 Coverage。

## 5. 常见测试模式的最低配方

| 模式 | 真实输入 | 核心断言 | 必查陷阱 |
| --- | --- | --- | --- |
| Converter/Mapper | 含代表字段的非空输入 | 关键字段映射、保留字段、条目内容 | 只断言非空；把 converter Mock掉 |
| Parser | 最小合法文本/文件片段，来自可解释语法 | 条目数、关键字段、顺序或错误位置 | 空文本只触发return；期望值由同parser算 |
| Validator | 一个合法样本与一个契约明确的非法样本 | 接受/拒绝、错误类型/码 | 任意异常都当正确，吞异常 |
| Service | 真实Service+可控边界返回 | 业务结果、状态或外部请求参数 | 把所有业务协作者Mock后只verify任意调用 |
| 分支/循环 | 满足guard的元素及代表分支变体 | 每项处理结果、数量及特征 | 永远emptyList，测试从不进循环体 |
| Spring/Repository | 最小必要上下文/隔离存储 | 框架行为、实际持久数据或响应 | 所有@Service都启动全应用；访问真实数据库 |

优先一条有效主路径，再补低成本重要分支/明确错误路径；不要求当前包穷尽组合。Boundary测试不是无效测试，但不能把“只覆盖空输入”当成复杂业务方法已经完成。

## 6. 具体例子（虚构教学契约，禁止直接加入业务仓库）

假定一个经批准的示例契约：`parse("A,2")` 返回一条记录，编号 A、数量 2；数量为负必须抛业务定义的 InvalidRowException。目标是 parser 的真实非空路径。

坏测试：Mock parser 返回一条假记录，或只传空字符串然后 assertNotNull。它不能约束解析行为。

好测试的配方：真实 parser；固定文本 `A,2`；断言集合恰好一个元素、id 为 A、quantity 为 2。负数场景单独测试确切异常类型/错误码，不 catch Throwable 后无条件通过。

```java
// 教学片段，类型名是假设；项目实现必须来自真实签名。
var rows = realParser.parse("A,2");
assertEquals(1, rows.size());
assertEquals("A", rows.get(0).id());
assertEquals(2, rows.get(0).quantity());
```

这一模式应能发现“漏写quantity”“数量固定为0”“重复返回两条”等合理错误。对于只有交互本身才是业务契约的 void 方法，校验精确请求参数、次数和禁止副作用可以是主要断言；不机械禁止 verify。只有不抛异常就是完整契约时，doesNotThrow才可作为主要断言，需说明依据。

## 7. 实施规则

实施者只能按配方修改允许测试/fixture；禁止改生产代码/POM/覆盖率工具、删除既有测试、停用测试、扩大 Mock 边界、用 broad suppression 隐藏类型/断言问题。

配方错误时返回 ANALYSIS_INVALID，附实际代码证据；不要偷偷换目标、换预期或自由扩成整类测试。可以提更合适的 fixture/层级，由分析者修订配方并重新签发工作包。

测试代码生成后，在隔离副本内通过现有局部入口编译/运行；普通失败可修 import、签名、初始化、资源路径、fixture、明确的Mock设置。发生生产缺陷/预期不明/环境故障时不顺手“修好一切”。

禁止把失败的新测试直接应用到接受工作区。隔离补丁未通过时保留 attempt 证据；撤回本次未接受补丁不等于删掉用户已有测试。

## 8. 轻量质量门禁，不追IDE全零黄色

必查：目标被Mock、恒真断言、异常被吞、未消费stub、死fixture、只走early-return、把生产算法复制到expected、未经解释的raw/unchecked、测试依赖顺序/真实时钟/网络。

未使用import、冗余变量等可自动安全修；IDE风格建议不全部阻塞。Mockito strict stubbing 若当前版本/测试基线已验证可用则复用，不能为了清警告更换mock maker。IDEA黄线是否清除只能由实际 inspection 结果证明，编译通过不能代替。

同模式第一个样板要由只读审查者检查“输入→目标路径→预期→断言”。高风险逻辑做少量隔离错误变体/PIT抽查；之后同模式可批量复用其 fixture 构造方法，但每个目标仍独立核对契约，不复制算法。

## 9. 失败反馈应该短而可操作

程序只向修复者发：准确阶段、失败测试、首个相关堆栈、expected/actual、目标方法before/after、补丁范围、剩余重试次数。

| 结果 | 下一动作 |
| --- | --- |
| 编译错误 | 修测试签名/类型，不删类 |
| 目标zero gain | 重新检查入口、guard、分派、Mock和exec采集，不堆同类测试 |
| 错误overload被覆盖 | 修调用参数/目标身份，不改验收粒度 |
| 新回归 | 修本次补丁；不能刷新历史失败baseline洗掉 |
| 预期不明 | 返回具体缺失契约，延期目标 |
| 数据/OOM/指纹异常 | 交程序暂停环境；测试Agent不得改manifest或POM |

默认修复预算见 DESIGN；相同根因重复失败不无限循环。分析模板复用也要绑定目标/源码/依赖hash，不能跨变更复用旧结论。

## 10. 四份短任务卡（由程序填真实引用，不手工复制整本指导书）

### 主 Agent

```text
读取当前状态摘要和本轮候选卡，只负责优先级、分析评阅与策略决策。
选一个可行任务或返回明确延期原因；不要修改任何文件、执行Maven或重建基线。
使用程序提供的合法动作，不自行创建下一Batch或宣布90%完成。
```

### 分析子 Agent

```text
只分析工作包中的精确Target，不修改文件。读取给定源码/调用方/有效样板与预期来源。
返回入口链和证据、每个关键进入条件及fixture控制方式、测试层级、具体Scenario、断言及依据。
检查已有测试是否Mock目标、空数据短路或走错继承/重载路径。
材料不足时请求具体上下文；不可行则ESCALATE/DEFER，不猜正确结果。
```

### 实施子 Agent

```text
只实现已批准Analysis中指定的Target、Scenario与断言，在本次隔离副本修改允许测试文件。
参考已验证样板，真实调用生产实现。禁止改src/main、POM、工具、状态、删除既有测试或停用断言。
发现配方与代码不符返回ANALYSIS_INVALID；不要换目标或自造预期。
提交补丁、workItemHash、analysisHash、修改文件和Scenario→测试→断言对应表，不自评VERIFIED。
```

### 审查/修复子 Agent

```text
审查时只读补丁、配方和真实测试/目标收益报告，检查预期来源、真实目标执行及断言判别力。
明确指出错误实现会被哪条断言捕获；证据不足不要仅因Coverage提高而通过。
修复时只改本次允许测试补丁，根据具体失败反馈处理；不得降低门禁、改生产或删除既有测试。
返回具体问题/补丁及未解项；程序拥有最终接受权。
```

## 11. 吞吐与指导书更新

不要在每个方法后完整clean verify。程序在包内批量生成/修复，包末做已批准模块回归和收益验证，按锁定周期做新鲜全量检查。

每轮记录有效目标数、目标新增行/分支、模型调用数、编译失败率、zero-gain率、返修轮数与时间。提升小不自动等于模型差；先排除分母、数据丢失、目标身份、入口和样例质量。相同模式连续失败，更新样板/避坑记录，而不是扩大类数量。

长期规范的修改需要明确实例和验收；本地有价值样板先留本地。上传公开仓库只能用去敏合成例子，不上传公司生产代码或真实设备数据。
